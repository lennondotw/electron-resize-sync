# Work log

Date: 2026-09-24

## Completed

- Banding: pure-grey tiles tried and reverted (`214757c`, `d7b4a30`); a noise
  overlay (`efd1c8d`, `1d865a8`) only masked edges, so it was replaced by
  per-tile blue-noise ordered dithering computed from the exact colour
  (`b3ca902`). [Tile dithering](../../experiments/2026-09-24/tile-dithering/README.md).
- Checked the display path for 10-bit output: it is 8-bit on the current
  display. [Display bit depth](../../experiments/2026-09-24/display-bit-depth/README.md).
- HUD: play/pause that freezes only the tiles while the loop and busy work keep
  running (`ff3da6c`, `c09f510`); busy work defaults to 30 ms (`30cc363`);
  settings persist to `localStorage` with a 200 ms leading/trailing throttle
  (`0fc77ba`).
- Resize synchronisation: measurement bridge (`edf186e`), paced resizing behind
  a `resize sync` switch (`b378089`), acks that carry the rendered size and an
  isolated user data directory for experiments (`8a3483f`).
  [Plan](../plans/2026-09-24/resize-sync.md).
- Experiment scripts with an isolation harness (`588c342`), covering every edge
  and corner in both directions (`0dbf83b`), and this documentation structure.
- Fixed paced resizing growing the wrong way: Electron's `will-resize` bounds
  on macOS keep the bottom-left corner fixed (`1853363`).
- Source reading of Chromium 152 and Electron 44.4.5 on resize synchronisation
  ([research](../research/2026-09-24/chromium-resize-sync.md)).
- Screen-recorded resize experiment with edge markers (`dac568f`) and a first
  series: baseline, pacing and three Chromium switches all fail
  ([record](../../experiments/2026-09-24/resize-recording/README.md)).
- Resize deadline: a binary patch of a copy of Electron 44.4.5 that forces the
  default surface deadline on resize (`13720c7`), located with the official
  breakpad symbols. Together with `--deadline-to-synchronize-surfaces=30` and
  `--disable-features=RemoteCoreAnimationAPI` it keeps the content in step in
  all 16 recorded drags; each part was shown necessary
  ([record](../../experiments/2026-09-24/resize-deadline-patch/README.md)).
- Cost of resize deadline: a main-process probe (`a7d1567`), a `yield on resize`
  switch (`127541b`) and controls with dithering off. The slow resize steps
  came from GPU load of the dithering masks; without it the patched build
  keeps pace and stays in step, blocking the main thread for up to one busy
  frame, or 34 ms with yield.

- Render before reveal behind `ELECTRON_RESIZE_SYNC_REVEAL`
  (`9f7010f`); a source patch for shipping resize deadline and app-set switches
  (`1979baf`); a click-through resize rate overlay (`63a9030`…`e55d000`).
- Recording tools on any display, background drags, and edge detection that
  ignores the drag tool's pointer (`60cbecc`…`6ceea54`).
- [Resize rate overlay record](../../experiments/2026-09-24/resize-rate-overlay/README.md)
  and [resize matrix on the built-in display](../../experiments/2026-09-24/resize-matrix-builtin/README.md).

- Correction to `1853363`: on macOS Electron's `will-resize` `details.edge`
  is only ever "right" or "bottom" (a guess from the larger size change), so
  paced resizing and the render-before-reveal window kept the top-left
  corner fixed for every drag. They now guess the dragged edges from the
  pointer, latched per drag; the guess is documented as unreliable in
  `drag-edge-heuristic.ts`. Checked by emitting `will-resize` with a stubbed
  pointer on each edge and corner (8 of 8), now a reproducible run:
  [drag-edge heuristic](../../experiments/2026-09-24/drag-edge-heuristic/README.md).
